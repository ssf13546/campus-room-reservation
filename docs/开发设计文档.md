## 1. 项目概述

### 1.1 选题背景

校园中的自习室、实验室、会议室等共享空间经常需要按照日期和时间段预约。如果仅靠人工登记或群聊接龙，容易出现以下问题：

- 同一房间同一时间段被多人重复预约；
- 预约时间冲突难以及时发现；
- 取消预约后时段没有及时释放；
- 房间使用情况无法统计；
- 历史预约记录难以查询。

本项目要求开发一个简化的自习室/会议室预约系统，实现空间查看、时间预约、冲突检测、取消预约和记录查询的完整闭环。

### 1.2 项目目标

完成“空间查看 → 可用时段查询 → 创建预约 → 冲突检测 → 取消预约 → 记录查询 → 使用统计”的完整业务闭环。

### 1.3 项目范围

必做功能：

- 空间/房间信息管理；
- 按日期查看可用时段；
- 创建预约；
- 取消预约；
- 我的预约 / 历史记录；
- 按房间或日期查询；
- 时间冲突检测；
- 预约统计与可视化。

可选 AI 扩展：

- 根据人数、日期、时间段和需求推荐合适房间；
- 自动生成会议安排摘要；
- 根据预约记录生成使用情况总结。

### 3.1 系统架构

采用 Flask 经典 MVC 分层结构：

```text
浏览器
  ↓
Flask 路由层（routes）
  ↓
业务逻辑层（services / 核心规则）
  ↓
```

前端使用：

- Jinja2 模板渲染页面；
- Bootstrap 负责基础布局和表单样式；
- ECharts 负责统计图表；
- 少量 JavaScript 负责交互和图表加载。

## 6. 核心业务逻辑设计

### 6.1 时间冲突检测

这是本项目的核心规则。

规则描述：

> 同一房间、同一天、状态为 booked 的预约中，如果新预约时间段与已有预约时间段存在重叠，则拒绝新预约。

时间重叠判断公式：

```text
已有开始时间 < 新结束时间
并且
已有结束时间 > 新开始时间
```

示例：

| 已有预约 | 新预约 | 是否冲突 |
|---|---|---|
| 14:00 - 15:00 | 14:30 - 15:30 | 冲突 |
| 14:00 - 15:00 | 15:00 - 16:00 | 不冲突 |
| 14:00 - 15:00 | 13:00 - 14:00 | 不冲突 |
| 14:00 - 15:00 | 13:30 - 14:30 | 冲突 |

> 友好提示：冲突命中时，若冲突的已有预约属于当前登录用户本人，返回“您已预约该时段”；否则返回“该时间段已被预约”。

### 6.2 冲突检测代码示例

```python
from datetime import datetime, date, time

def has_conflict(room_id, reserve_date, new_start, new_end):
    conflict = Reservation.query.filter(
        Reservation.room_id == room_id,
        Reservation.date == reserve_date,
        Reservation.status == 'booked',
        Reservation.start_time < new_end,
        Reservation.end_time > new_start
    ).first()

    return conflict is not None
```

### 6.3 创建预约流程

```text
接收表单
  ↓
校验房间是否存在、是否维护中
  ↓
校验日期是否合法、是否过去
  ↓
校验开始时间 < 结束时间
  ↓
校验人数是否超过容量
  ↓
调用 has_conflict() 检测冲突
  ↓
无冲突则写入 reservations 表，status = booked
  ↓
返回预约成功页面
```

### 6.4 取消预约流程

```text
用户点击取消
  ↓
校验预约是否存在
  ↓
校验当前用户是否有权取消
  ↓
校验预约状态是否为 booked
  ↓
校验预约是否已过期（date + end_time 已过则视为已完成，不可取消）
  ↓
更新 status = cancelled，记录 cancelled_at
  ↓
该时间段自动释放，可被重新预约
```

### 6.5 业务规则清单

| 编号 | 规则 | 处理方式 |
|---|---|---|
| R01 | 同一房间时间重叠必须拒绝 | 返回“该时间段已被预约” |
| R02 | 开始时间必须早于结束时间 | 表单校验 + 后端校验 |
| R03 | 已取消预约释放时段 | 冲突检测过滤 cancelled |
| R04 | 不能预约维护中的房间 | 房间状态校验 |
| R05 | 不能预约过去的日期 | 日期校验 |
| R06 | 人数不能超过房间容量 | 容量校验 |
| R07 | 用户只能取消自己的预约 | 权限校验 |
| R08 | 已完成预约不能再次取消 | 状态校验 |
| R09 | 重复提交应受控 | 前端禁用按钮 + 后端幂等检查 |
| R10 | 非法输入应有明确提示 | 异常处理 |
| R11 | 过期预约视为已完成，不可取消 | 页面加载时刷新状态 + 取消时二次校验 |
| R12 | 有预约记录的房间不可删除 | 删除前校验，存在预约则拒绝 |

### 6.6 预约状态流转与完成机制

状态流转：

```text
booked ──取消──▶ cancelled
booked ──过期──▶ completed
```

- 预约创建后状态为 `booked`；
- 用户主动取消：`booked → cancelled`，记录 `cancelled_at`；
- 系统动态完成：预约的 `date + end_time` 早于当前时间时视为已完成。系统在加载“我的预约 / 历史记录 / 统计看板 / 管理后台”等页面时调用 `update_completed_reservations()`，将已过期且仍为 `booked` 的记录批量更新为 `completed`（写库，保证数据闭环），无需定时任务；
- 取消校验时同样执行一次过期判断，已过期预约直接拒绝取消并提示“该预约已完成，无法取消”。

## 8. 异常处理设计

| 异常场景 | 触发条件 | 系统处理 |
|---|---|---|
| 空房间名称 | 管理员提交空名称 | 提示“房间名称不能为空” |
| 非法容量 | 容量 <= 0 | 提示“容量必须为正整数” |
| 非法时间 | 开始时间 >= 结束时间 | 提示“开始时间必须早于结束时间” |
| 过去日期 | 预约日期 < 今天 | 提示“不能预约过去的日期” |
| 时间冲突 | 同一房间时间重叠 | 提示“该时间段已被预约” |
| 重复预约 | 同一用户同一房间同一时段 | 提示“您已预约该时段” |
| 房间维护中 | room.status = maintenance | 提示“该房间正在维护，暂不可预约” |
| 人数超限 | attendees > capacity | 提示“人数超过房间容量” |
| 人数非法 | attendees < 1 或非整数 | 提示“人数必须为 1 到容量之间的正整数” |
| 越权取消 | 用户取消他人预约 | 提示“无权取消该预约” |
| 重复取消 | 预约状态不是 booked | 提示“该预约已取消或已完成” |
| 预约不存在 | ID 无效 | 返回 404 或提示“预约不存在” |
| 取消过期预约 | 预约 date + end_time 已过 | 提示“该预约已完成，无法取消” |
| 删除有预约的房间 | 房间存在预约记录 | 提示“该房间存在预约记录，无法删除” |
| 错误文件/空数据 | 统计无数据 | 图表显示“暂无数据” |

本项目允许使用 Cursor、GitHub Copilot、Claude Code 等 AI 编程工具。AI 主要参与以下环节。

### 9.1 需求分析

关键 Prompt 示例：

```text
我要做一个校园自习室/会议室预约系统，请帮我梳理核心业务规则、异常场景和数据库表。
要求：同一房间时间重叠必须拒绝；取消后释放时段；用户只能取消自己的预约。
```

AI 输出用途：

- 生成用户故事；
- 补充异常场景；
- 梳理状态流转；
- 设计数据库字段。

人工验证：

- 检查是否覆盖题目必做功能；
- 检查业务规则是否与题目一致；
- 删除不合理扩展，控制项目范围。

### 9.2 代码生成

关键 Prompt 示例：

```text
请用 Flask + SQLAlchemy 写一个时间冲突检测函数。
输入：room_id, date, new_start, new_end。
规则：同一房间、同一天、status='booked'，已有开始 < 新结束 且 已有结束 > 新开始，则冲突。
```

AI 输出用途：

- 生成冲突检测函数；
- 生成 CRUD 路由骨架；
- 生成 ECharts 配置；
- 生成 Bootstrap 表单模板。

人工验证：

- 用 14:00-15:00 和 14:30-15:30 测试冲突；
- 用 15:00-16:00 测试不冲突；
- 检查取消后能否重新预约。

### 9.3 调试

关键 Prompt 示例：

```text
Flask 报错：sqlalchemy.exc.StatementError: SQLite DateTime type only accepts Python datetime and date objects as input.
请帮我定位原因并给出修改方案。
```

AI 输出用途：

- 解释错误原因；
- 给出类型转换代码；
- 建议使用 datetime.strptime。

人工验证：

- 重新运行；
- 检查数据库写入；
- 检查页面提示。

### 9.4 测试

关键 Prompt 示例：

```text
请为预约系统生成边界测试用例，包括：
开始时间等于结束时间、时间部分重叠、时间完全包含、取消后重新预约、越权取消。
```

AI 输出用途：

- 生成测试用例表；
- 生成 pytest 测试代码；
- 补充异常输入。

人工验证：

- 逐条手工执行；
- 记录实际结果；
- 修复不符合预期的逻辑。

### 9.5 代码审查

关键 Prompt 示例：

```text
请审查以下 Flask 预约代码，检查是否存在 SQL 注入、明文密码、硬编码密钥、重复代码和越权风险。
```

AI 输出用途：

- 发现安全隐患；
- 建议使用密码哈希；
- 建议配置项放入环境变量；
- 建议抽取重复校验逻辑；
- 建议正式部署时补充 CSRF 防护（Flask-WTF / CSRFProtect）。

人工验证：

- 修改代码；
- 重新测试；
- 在 README 中记录 AI 使用情况。

## 11. 部署与启动

### 11.1 环境要求

- Python 3.9+
- pip
- 现代浏览器

### 11.2 安装依赖

```bash
pip install -r requirements.txt
```

requirements.txt 示例：

```text
Flask
Flask-SQLAlchemy
Flask-Login
Werkzeug
```

> 说明：本项目不依赖 Flask-Migrate、Flask-WTF，数据库初始化使用 `init_db.py`。

### 11.3 初始化数据库

```bash
python init_db.py
```

脚本会执行 `db.create_all()` 建表并创建默认账号。如需手动建表：

```python
with app.app_context():
    db.create_all()
```

### 11.4 启动项目

```bash

```

浏览器访问：

